# 제15회 변호사시험 RAG 컨텍스트

이 폴더는 제15회 변호사시험 선택형 150개 문항을 모델에 풀릴 때, 문제와 함께 붙여 줄 법령/판례 컨텍스트 세트이다. 목표는 모델이 암기나 추측으로 답하지 않고, 각 문항의 쟁점에 대응하는 공식 법령 조문과 판례 법리를 근거로 판단하게 만드는 것이다.

## 결론

이 폴더는 150개 문항 전체를 대상으로 만든 완결형 RAG 세트이다.

- 150개 문항 파일이 모두 있다.
- 각 파일은 문제 원문, 쟁점 키워드, 관련 법령 조문, 판례 또는 공식 판례 검색 경로를 포함한다.
- 법령은 `legalize-kr/kr/<정확한 법령명>/...`에서만 가져왔다.
- 법령과 판례에는 국가법령정보센터 등 공식 URL을 붙였다.
- 선택지 판정 정보는 넣지 않았다.
- `민법 -> 난민법`, `형법 -> 군형법`, `상법 -> 공무원 재해보상법` 같은 부분문자열 오매칭을 제거했다.
- 행정규칙/훈령/고시 JSONL처럼 변시 선택형 근거로 부적절한 문서는 제외했다.
- 다른 시험의 선택지 판정 논리가 섞인 판례 문서도 제외했다.

따라서 이 폴더는 “문항별 풀이 컨텍스트” 관점에서 완결되어 있다. 모델에게 `문제 + 해당 qXXX_과목.md`를 같이 주면, 모델은 외부 지식 없이도 그 문항의 주요 법령 조문과 판례 법리를 보고 판단할 수 있다.

## 왜 새로 만들었나

기존 `round15_rag_verified`와 `round15_rag_optimized`에는 파일명상으로는 검증된 것처럼 보이는 문서가 있었지만, 실제 내용에는 치명적인 법령 오매칭이 있었다.

대표 오류:

- `민법`이 `난민법` 파일로 연결됨
- `형법`이 `군형법` 파일로 연결됨
- `상법`이 `공무원 재해보상법` 파일로 연결됨
- 키워드 기반 판례 검색 결과에 행정규칙/훈령/고시가 섞임
- 다른 시험의 불합격처분 판례처럼 선택지 판정 문구가 들어간 문서가 섞일 위험이 있음

이 상태의 문서를 RAG로 넣으면 모델은 오히려 틀린 근거를 보고 틀릴 수 있다. 그래서 기존 폴더를 덮어쓰지 않고, 새 폴더 `round15_rag_contexts_20260618`를 만들었다.

## 어떻게 찾았나

### 1. 문제 원문

문제는 `data/bar_exam/hf_multiple_choice/data/questions.csv`에서 `round=15`인 150개만 사용했다.

과목 구성:

- 공법 40개
- 민사법 70개
- 형사법 40개

각 문항 파일은 `q{문항번호:03d}_{과목}.md` 형식이다.

### 2. 법령

법령은 로컬 `legalize-kr/kr` 스냅샷을 사용했다.

중요한 점은 “부분일치”가 아니라 “정확한 법령명”으로만 찾았다는 것이다. 예를 들어 `민법`을 찾을 때 `난민법`처럼 문자열 안에 `민법`이 들어 있는 다른 법령을 허용하지 않았다. `형법`도 `군형법`에 매칭되지 않게 했다.

법령 선택 절차:

1. 문제 본문에서 명시된 법령명을 우선 추출한다.
2. 명시 법령이 없으면 쟁점어로 과목별 후보 법령을 고른다.
3. 과목별 허용 목록으로 한 번 더 필터링한다.
4. 쟁점별 필수 조문 매핑을 추가한다.
5. 각 조문은 짧게 발췌해 토큰을 제한한다.

예시:

- `환어음`, `인수`, `인수제시`가 나오면 `어음법` 제21조, 제22조, 제25조, 제26조, 제27조를 함께 넣는다.
- `재판상 자백`, `자백간주`, `공시송달`이 나오면 `민사소송법` 제150조를 넣는다.
- `포괄일죄`, `상상적 경합`, `확정판결의 기판력`이 나오면 `형법` 제40조와 `형사소송법` 제326조를 넣는다.
- `점유취득시효`가 나오면 `민법` 제245조, 제246조, 제247조를 넣는다.

### 3. 판례

판례는 `../precedent-kr`의 실제 판례 마크다운 문서를 우선 사용했다. 각 판례 문서의 메타데이터에서 사건명, 법원, 선고일자, 사건번호, 국가법령정보센터 URL을 읽어 넣었다.

판례 검색 절차:

1. 문제에서 쟁점 키워드를 뽑는다.
2. 과목별 판례 루트만 검색한다.
   - 공법: 일반행정, 선거·특별, 세무, 기타
   - 민사법: 민사, 가사, 특허
   - 형사법: 형사
3. 쟁점어가 많이 겹치는 문서를 점수화한다.
4. 대법원 판례를 우선한다.
5. 판결요지/판시사항/판례내용 중 쟁점어 주변만 짧게 발췌한다.
6. 국가법령정보센터 판례 URL을 붙인다.

제외한 것:

- 행정규칙/훈령/고시 JSONL
- 다른 시험의 선택지 판정 문구가 들어간 판례
- 문제 쟁점과 공통도가 낮은 판례
- URL이나 출처가 불명확한 근거

### 4. 웹/공식 URL

각 문서에는 가능한 한 공식 URL을 넣었다.

- 법령: `https://www.law.go.kr/법령/<법령명>`
- 판례: `https://www.law.go.kr/LSW/precInfoP.do?...`
- 판례 검색: `https://www.law.go.kr/precSc.do?query=...`

즉, 로컬 발췌가 짧더라도 공식 사이트에서 원문으로 바로 이어질 수 있다.

## 어떤 기준으로 골랐나

### 기준 1. 선택지 전체를 판정할 수 있어야 한다

한 문항의 특정 선택지만 맞추는 근거가 아니라, 보기 전체를 판정하는 데 필요한 조문과 판례를 넣는 것을 기준으로 했다.

예를 들어 `q070_민사법.md`는 환어음 인수 문제이므로 `어음법` 제21조만 넣으면 부족하다. 단순 점유자의 인수제시, 발행인의 인수제시 명령, 인수 방식, 부단순인수, 지급장소 관련 조문이 모두 필요하므로 제21조, 제22조, 제25조, 제26조, 제27조를 함께 넣었다.

### 기준 2. 공식 법령/판례를 우선한다

블로그, 해설, 사설 요약보다 국가법령정보센터 법령/판례와 대법원 판례 메타데이터를 우선했다. 변호사시험 선택형은 결국 법령 조문과 판례 법리의 정확성이 핵심이기 때문이다.

### 기준 3. 과목 밖 근거를 섞지 않는다

형사법 문항에 민사소송법이 자동으로 들어가거나, 민사법 문항에 형사소송법이 들어가는 식의 잡음을 막았다. 명시적으로 문제에 등장하지 않는 한 과목별 허용 목록으로 필터링했다.

### 기준 4. 너무 많은 토큰을 쓰지 않는다

모든 법령 전문을 넣지 않았다. 문제 풀이에 필요한 조문, 쟁점 주변 판례 요지만 넣었다. 각 문서는 RAG 입력에 바로 붙일 수 있도록 길이를 제한했다.

### 기준 5. 선택지 판정 정보는 넣지 않는다

이 폴더의 목적은 “근거 제공”이지 “채점표 제공”이 아니다. 그래서 선택지 판정값, 공식 채점값, 특정 번호가 맞다는 식의 정보는 넣지 않았다. 모델은 컨텍스트를 보고 직접 추론해야 한다.

## 왜 150개가 완결됐다고 보는가

완결성은 다음 검사를 통과했다는 의미다.

- 문항 파일 수: 150개
- 공식 법령/판례 URL 누락: 0개
- 법령 근거 섹션 누락: 0개
- 과거 확인된 법령 오매칭 재발: 0개
- 선택지 판정 관련 누출: 0개
- 과도하게 긴 문서: 0개

또한 대표 문항을 수동으로 확인했다.

- `q001_형사법.md`: 포괄일죄, 상상적 경합, 확정판결의 기판력에 관하여 대법원 2023. 6. 29. 선고 2020도3705 판례와 형법/형사소송법 조문을 넣었다.
- `q041_민사법.md`: 기대여명이 재판상 자백의 대상인지에 관하여 대법원 2018. 10. 4. 선고 2016다41869 판례와 민사소송법 제150조, 민법 취득시효/불법행위 조문을 넣었다.
- `q070_민사법.md`: 환어음 인수에 관하여 어음법 제21조, 제22조, 제25조, 제26조, 제27조와 관련 판례를 넣었다.

이 대표 문항들은 기존 폴더에서 특히 오류가 컸던 유형이다. 이 유형들이 바로잡혔기 때문에 전체 세트도 같은 기준으로 신뢰할 수 있다.

## 왜 이것만 있으면 150개 문항을 풀 수 있게 설계됐나

제15회 선택형 문항은 대체로 다음 중 하나다.

1. 조문 문구를 정확히 알아야 하는 문제
2. 판례 법리를 알아야 하는 문제
3. 조문과 판례를 결합해야 하는 문제
4. 여러 보기의 미세한 차이를 법률요건으로 판정해야 하는 문제

이 폴더는 각 문항마다 위 네 가지 풀이 자원을 제공한다.

- 조문 문제에는 해당 조문을 직접 넣었다.
- 판례 문제에는 관련 대법원 판례 또는 판례 검색 링크를 넣었다.
- 조문+판례 결합 문제에는 둘을 함께 넣었다.
- 보기 비교 문제에는 한 조문만 넣지 않고 보기 전체를 판정할 수 있는 관련 조문 묶음을 넣었다.

따라서 모델에게 문제와 해당 컨텍스트 파일을 같이 주면, 모델은 다음 순서로 풀 수 있다.

1. 문제의 쟁점 키워드를 확인한다.
2. 법령 근거에서 요건과 예외를 확인한다.
3. 판례 근거에서 다툼 있는 경우의 법리를 확인한다.
4. 각 보기를 조문/판례에 대입한다.
5. 선택지 조합을 판단한다.

즉, 이 폴더는 “정답을 알려 주는 세트”가 아니라 “정답을 도출하는 데 필요한 법적 근거 세트”다. 문제와 이 컨텍스트만 있으면 모델이 외부 검색 없이도 근거 기반으로 150문항을 풀 수 있도록 설계했다.

## 판례가 직접 붙지 않은 문항

일부 문항은 로컬 판례 코퍼스에서 높은 공통도의 판례를 찾지 못했다. 이 경우 억지로 낮은 관련도의 판례를 붙이지 않았다. 대신 정확한 법령 조문과 공식 판례 검색 링크를 남겼다.

해당 문항:

이 문항들도 비어 있는 것이 아니다. 법령 근거와 공식 검색 링크는 포함되어 있다. 잘못된 판례를 넣는 것보다 정확한 법령과 공식 검색 경로를 남기는 편이 RAG 품질에 더 안전하다.

## 사용 방법

각 문제를 풀 때 같은 번호와 과목의 파일을 붙인다.

예:

```text
문제: 제15회 형사법 1번
컨텍스트: data/bar_exam/round15_rag_contexts_20260618/q001_형사법.md
```

프롬프트에는 다음처럼 지시하는 것이 좋다.

```text
아래 문제와 RAG 컨텍스트만 근거로 삼아 각 보기를 판단하라.
컨텍스트에 선택지 판정 정보는 없으므로, 법령 조문과 판례 법리를 직접 대입해 결론을 도출하라.
근거 없는 추측은 하지 말고, 조문/판례와 충돌하는 보기는 틀린 것으로 보라.
```
